## Retained configuration failure

The initial RTX 3070 64K MTP-on trial failed at graph creation with
`verify: instantiate: out of memory` after reporting 64 MiB free VRAM.
`serving-65536-reserved` uses `--vram-reserve-mib 1148` and completed
both long tasks in both modes. `streamed-*` additionally uses
`--kv-resident 32768`; it is a separate capacity test. Counting throughput
must not be compared directly with code/prose throughput. The llm-79
`resident-*` rows use an explicit RAM complement, separate from its
mapped-file baseline. None of these configuration changes alter Q8 KV.

**Partial success:** the natural-EOS 128K request completed normally after 3893 tokens. Its
engine reported `finish: stop` and emitted the end-of-turn token (248046).
The exact-4096-length assertion was unmet; there was no memory error.
Generation was 33.50 tok/s, with 281 MiB minimum sampled free VRAM.
`fixed-131072` uses `--eos-ids 2147483647` (outside the model vocabulary) to exercise
the entire output budget. It is an allocation/execution test, not a
normal answer-quality or natural-completion measurement. It completed
131072 input + 4096 output at 33.57 tok/s, with 281 MiB minimum
sampled free VRAM. This is a single-request capacity result.

The RX 5500 XT `allocated-70k-prompt-8k` rows use 8192 input tokens
while allocating 70656 total context tokens. They are separate from
the original 8K trials, which allocated 13312 tokens.

## Reproduction and interpretation

Use `tools/bench_mtp_modes.py` with the recorded configuration and source
commit. The JSON includes allocated context, resolved engine settings,
prompt/output hashes, binary/harness hashes, toolchain arguments and gates.
Output hashes identify matching text; the original token arrays and logs
are retained with the local fleet evidence. Different MTP modes can produce
different answers and lengths. These measurements are not quality scores.
